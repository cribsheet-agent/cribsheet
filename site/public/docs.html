How the exam worksand how to check it.

Four copies of the same AI agent sit the same exam every hour about what happened on Robinhood Chain in the hour before. Only the notes they bring differ. A script reads every answer key from the chain before any agent starts, so no model grades a model.

  • Chain Robinhood Chain (4663)
  • Source Pons launch factory
  • Schedule minute 1 of every hour, UTC
  • Live since 26 Nov 2026

01An exam hour

At minute 1 of every UTC hour a Cloudflare Workflow examines the hour that just closed. The steps run in this order, and each one writes to the public record.

  1. QuestionsEight questions about tokens launched on the Pons factory in that hour. The choice comes from a seed (keccak256("cribsheet:<hour>:<hash of the hour's first block>")), so anyone can regenerate it.
  2. KeysA script reads every answer from logs and contract calls at the chain head, before any agent starts. Every key except creator tax is read two independent ways. If the two readings disagree, the question is dropped and the drop is recorded.
  3. AnswersThe four arms answer at the same time with the same model, prompt, tools and call budget. Every tool call is kept.
  4. GradingEach answer is compared with the key by exact match. No model is asked whether an answer is right.
  5. NotesSelf rewrites its notes from the hour: its answers, the keys, how each key was read, and the fact check of its old notes.
  6. SealThe hour's bytes are published at /data/seal/<hour>. Their SHA-256 is written to CribsheetSeals on chain (0xfe6d4f39ca6732af967b941e8051d773f2c6011a) once per hour, and can never be changed.

A missed hour is recorded as missed, with the reason. It is never filled in later.

02The four arms

All four share one model (@cf/openai/gpt-oss-120b on Cloudflare Workers AI, temperature 0), one system prompt, three tools (rpc for read-only JSON-RPC, keccak, answer) and one call budget. The last block of context is the only difference.

ArmReads before the examQuestion it answers
Blank"You have no notes."How far do tools alone go?
ManualA fixed manual, frozen before hour 0Is good documentation enough?
SelfIts own notes, rewritten after every hourDoes memory beat a manual?
CrowdSelf's notes plus lessons from holders that passed a test (none yet: lessons are planned)Can people make an agent better?

Tool limits are the same for every arm: read-only methods only, eth_getLogs returns the count and at most 25 logs, long results are cut to 4,000 characters.

04Grading

Exact match after normalising: addresses to lowercase, numbers to integer strings, yes and no to one form. A block number off by one is wrong. Fewer tool calls breaks a tie.

05Notes and the fact check

An agent that writes its own notes will sometimes write things that are not true. Before every exam the checker reads the notes of Self and Crowd and tests each fact against the chain:

  • every event topic must appear in real factory logs, or be the hash of an event in the factory's verified ABI or ERC-20;
  • every 4-byte selector must return data from a real call;
  • every event or function named in the notes must exist in the verified ABI, or answer on chain.

Each item is marked seen, cracked (never seen on chain) or untestable. Cracked lines stay in the record; they are never deleted from the history. Self sees the cracked list when it rewrites its notes.

06Public data

Everything the exam produces is served under https://cribsheet.pro/data/, readable from any origin.

PathHolds
/data/results.jsonlOne line per hour: status, block window, key block, seed, scores, cost, and every question with its key, key sources, key calls and each arm's answer
/data/state.jsonNext hour, current level and Self's current notes
/data/transcripts/<hour>/<arm>.jsonEvery tool call and reply of one arm in one hour
/data/notes/<arm>/<hour>.mdThe exact context block an arm read that hour
/data/check/<hour>.jsonThe fact check of Self's notes before that hour
/data/seal/<hour>The bytes the hour's seal hash is computed from
Scores of every hour
curl -s https://cribsheet.pro/data/results.jsonl \
  | jq -c '{hour, status, score}'
The same in JavaScript
const text = await (await fetch('https://cribsheet.pro/data/results.jsonl')).text();
const hours = text.trim().split('\n').map(line => JSON.parse(line));
console.log(hours.at(-1).score);

Field names only grow: after hour 0 a field can be added, never renamed or removed. The schema is spec/results.schema.json. Records of the test runs before hour 0 are in records/f0.

07Check it yourself

Every key comes with the calls that produced it (key_calls), so you can read it again from any Robinhood Chain RPC. The curve key from the grading example, read from the public RPC:

getLaunchedToken(0x6aa9…9a05), word 1 is the curve
curl -s https://rpc.mainnet.chain.robinhood.com \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_call","params":[{"to":"0x7ed598bcef8bd9edd8c97a195c6d13f40801ec7e","data":"0x3cf28b5a0000000000000000000000006aa9decc666225ef82d55ad364d96c3e0e9d9a05"},"latest"]}'

In the result, the second 32-byte word ends in 0ffa57c97da367731d34ed758c046a2a39d0b18f, the key in the record.

To check a seal, hash the published bytes and compare with rootOf(hour) on the seal contract. node tools/verify-seal.ts <hour> in the repository does both and also checks the hashes inside the seal:

Hash of hour 0's seal bytes
curl -s https://cribsheet.pro/data/seal/0 | shasum -a 256

The whole method, word for word, is in METHOD.md. Where the code and that file differ, it is a bug.
