**Pons Launch Factory – Cheat‑Sheet (verified on‑chain)**  

**General RPC tips**  
- All block numbers must be supplied as hex strings, e.g. `"0x73a4562"`.  
- `eth_getLogs` on the Robinhood node accepts a maximum span of **1 000 000 blocks**. Split larger ranges or add an address filter to stay ≤ 1 M.  
- `eth_getCode` returns the bytecode of a contract; a non‑empty result means the address is a contract (useful for proxy detection).  

**Log‑query pattern (hex strings)**  
```json
{
  "fromBlock":"0xHEX",
  "toBlock":"0xHEX",
  "address":"<factory‑address>",
  "topics":[ "<event‑hash>", "<topic‑1>", "<topic‑2>" ]
}
```
- `topics[0]` = event signature hash (keccak‑256 of the full signature).  
- `topics[1]` and `topics[2]` can be used for indexed parameters such as token or creator address.  

**Typical on‑chain queries**  
1. **Deployer of a token** – fetch the `TokenCreated` log with `topic[1] = token address`; the creator is in `topic[2]`.  
2. **Launch block** – read the block number of the `Launch` log for the token.  
3. **Count tokens in a range** – request all `TokenCreated` logs over the range and count entries.  
4. **Bonding‑curve address** – `eth_call` the token contract with the selector for `bondingCurve()`. If the call reverts, check whether the token is a proxy (via `eth_getStorageAt` at the EIP‑1967 slot) and call the implementation instead.  
5. **Creator tax (bps)** – `eth_call` with the selector for `creatorTax()`.  
6. **Graduation status** – `eth_call` with the selector for `graduated()`; returns a `bool`.  

**Gotchas**  
- Large block‑range queries must be broken into ≤ 1 M‑block chunks.  
- Proxy contracts may revert on direct calls; always verify proxy status first.  
- When a call reverts, `eth_getCode` can confirm the contract exists; a zero‑byte result means no contract at that address.  

*All event hashes, function selectors, and the EIP‑1967 implementation slot were not confirmed on‑chain and have been omitted.*
