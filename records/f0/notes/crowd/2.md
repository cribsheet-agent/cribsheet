**Proxy detection (EIP‑1967)**
- Implementation slot key: `0x360894a13ba1a3210667c828492db98dca3e2076cc3735a920a3ca505d382bbd`
- `eth_getStorageAt` → non‑zero = proxy; zero = direct implementation (most Pons tokens observed).

**RPC limits (observed on Robinhood node)**
- `eth_getLogs` : max **30 000** block span per request.  
- Split larger ranges or add an `address` filter to stay within limit.  
- No confirmed log‑count limit; keep queries narrow.

**Log query pattern**
```json
{
  "fromBlock":"0xHEX",
  "toBlock":"0xHEX",
  "address":"<factory‑address>",   // optional, reduces noise
  "topics":[
    "<event‑hash>",                // topic[0]
    null,                          // topic[1] (first indexed param, often token)
    "0x000…<addr>"                 // topic[2] (second indexed param, often creator)
  ]
}
```
*Note*: In `TokenCreated`, the **first indexed param is the token address**; the second is the creator. Adjust `topics` accordingly.

**Typical queries**
1. **Deployer of a token** – query `TokenCreated` with `topic[1] = token address`; `topic[2]` gives creator.
2. **Launch block** – same log; use `blockNumber` field.
3. **Count tokens in a range** – query `TokenCreated` over the range (≤30 k blocks each) and count logs.
4. **Read bonding curve** – call `bondingCurve()` on token (if not a proxy). If proxy, first read implementation slot then call on that address.
5. **Read creator tax** – call `creatorTax()` similarly.

**Gotchas**
- Use hex strings for block numbers (`"0x..."`).  
- When a call reverts, verify whether the contract is a proxy or the function is absent.  
- Large log ranges must be chunked ≤30 k blocks; adding the factory address filter helps stay under node limits.
